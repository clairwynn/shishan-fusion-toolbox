# 标签流完整规范（NovelAI / SD全系 / Anima / NoobAI / Illustrious）

先看到画面，再翻译成标签。以 Danbooru 标签为主体，按画面需要混用自由英文短语与自然语言句子；稳定视觉属性由标签承担，动作互动、空间关系、构图指令、概念融合用句子表达。不设句数、标签数、总长度上限——画面完备优先，该多就多。

## 总则

- **拼写统一空格形态**：`long hair` 不是 `long_hair`。例外：`score_*` 保留下划线；`=_=`、`^_^`、`>_<` 等符号标签保持原样。
- **质量前缀一律不加**：不写 masterpiece、best quality、high quality、very aesthetic、4k、8k、highres、newest 等泛质量词与年代词。
- **默认不加权**：全部原样权重。实测某层效果不足时才对该层加权，优先考虑换更精确的标签而不是堆权重。负权重属进阶技巧。
- **画师标签**：用户点名画师才写，不自己发明画师串；Anima 下 artist 必须加 `@` 前缀。
- **标签密度**：相关词可协同表现同一构思（同一对象的不同动作、形态、材质、视觉效果可同时描述）；只删没有增加信息的同义重复，不按标签数量判断画面是否过载。
- **环境有实体，服装有材质**：用至少 3 个环境实体支撑空间；服装写出必要材质与质感。用户明确要求纯背景/留白时服从用户。
- **不写"european town"这类宽泛场景**——写那个镇上有什么（具体道具清单构建活着的空间）。

## 库查询（标签的唯一来源）

主库：`database/tags/tags.tsv`（UTF-8，无表头，约32.8万行，按名称字母序）。每行三列 TAB 分隔：`标签名 / 中文名 / 类别码`。类别码：0=general、1=artist、3=copyright(系列)、4=character、5=meta。

先把库的**绝对路径**解析出来（从 skill 加载时的 base directory 推导），之后每次 grep 都用绝对路径。查询模式（`-P` 必须带；`\t` 与 `\Q\E` 依赖 PCRE）：

```bash
# 中文 → 标签（精确匹配中文名列）
grep -P "\t\Q长发\E\t" "<ABS>/tags.tsv"
#   long_hair  长发  0

# 中文模糊（前缀/子串，用于不确定库内叫法时）
grep -P "\t银" "<ABS>/tags.tsv" | head -20
grep -P "\t.*银" "<ABS>/tags.tsv" | head -20

# 标签 → 中文（精确匹配标签名，行首锚定）
grep -P "^\Qschool_uniform\E\t" "<ABS>/tags.tsv"

# 含元字符的标签必须用 \Q...\E 包住（角色名带括号极常见，
# 裸写会被当正则分组而假性零命中，如 silver_wolf_(honkai:_star_rail)）

# 英文模糊（查近义、找候选）
grep -iP "school.uniform\t" "<ABS>/tags.tsv" | head -20
```

要点：

- 结果按名称字母序返回；**所有词条同级**——展示候选时不排序、不推荐、不附热度，选择权在用户。
- 精确零命中 ≠ 标签不存在，先模糊复查再下「库里没有」的结论。
- 同一中文可命中多行跨类别（如「长发」同时命中 artist 与 general）——描述画面取 category 0 的行，别把 artist 误当外观标签。
- 库内存下划线形态（`school_uniform`），写进提示词转空格（`score_*` 除外）。
- **命中处理四态**：唯一命中→直接采用；多候选→逐个问用户（附中文，不排序）；精确+模糊均零命中→先走辅助库回退链，仍无才判「库外」→给最近的2-3个库内候选（附中文）+问用户；用户明确指定的标签按原文保留。
- **辅助库回退链**（判「库外」前必走）：tags.tsv 换模糊模式复查 → `tag-aliases.csv`（中日韩别名反查）→ `tags-wdv3.json`（第二词库，`grep -n '"tag名"'` 检索）→ 全部零命中才下结论。各文件格式与查询命令见 [database/MANIFEST.md](../database/MANIFEST.md)。**注**：本环境无 `rg`，一律用 `grep`（含元字符的关键词加 `-F`）。
- 角色知识库（`database/characters/`）检索方法见 MANIFEST。角色查证链：本地角色库 → WebSearch 官方设定 → 问用户要参考图（WebSearch 不可用时降级为「本地库 → 问用户」并说明；其余异常处理见 SKILL.md §异常与降级）。禁止凭记忆写版权角色外貌。

## 正向组装顺序

**本节是 models.md §组装顺序总则【权威】在标签流下的展开**，冲突时以总则为准。通用骨架（各模型差异见 models.md）：

```
[人数 1girl/1boy/1other] → [角色] → [系列] → [@artist（有则写）] → [主体特征] → [服装] → [动作姿势] → [场景] → [构图镜头] → [风格]
```

- 画面有人物时人数标签必写——它是构图第一锚点；纯风景/静物不写（用户要负面词时提示在负向补 `1girl`/`1boy` 防人物乱入）。
- 角色 → 系列成对出现（角色库命中通常自带作品名）。
- **动作在场景/镜头之后**（NAI 有意偏离官方顺序的理由见 models.md §组装顺序总则）。
- **质量尾不存在**——本skill 不写质量前缀，骨架里不保留该占位。
- **位置是隐性权重**：灵魂元素优先，身份与人数随后，按视线路径组织属性；不是把角色模板整块贴在开头，打散位置不等于丢失辨识特征。
- **权重服务焦点**：需要加权时核心概念高于支撑概念，相关概念可打包加权；不把角色分区问题交给高权重解决。

## 词组与句子的判据（混合写法核心）

**句子在写"关系"时更准，词组在写"离散事实"时更准。**

**必须词组化的九类**（写成句子模型抓不稳）：人数与主体（`1girl, solo`——只在最开头出现一次）；种族体征（`cat ears, fox ears, horns, wings`——`she has cat ears` 不如直接 `cat ears` 稳）；镜头与视角含机位高低（`full body, close-up, cowboy shot, from below, from above, dutch angle`——**机位归 tag，占画幅比例归句子**）；姿势与体位（`sitting, kneeling, leg up, arm support, head rest`——实测姿势句子执行不清）；服装状态（先查语义再用词）；部位锚定（`ass focus, foot focus` 稳，`navel focus, thigh focus` 优先改句子）；IP与角色名；版式与背景形态（`comic, 4koma, multiple views, chibi, simple background, blurry background`）；V5 专有开关（`low/medium/high/ultra complexity`、`transparent background`、`has alpha`、`depthness`——功能开关不是质量尾，默认不加）。

**必须写成句子的七类**：空间关系与归属（多人防串味的主要手段）；职能与归属（角色 tag 不带群体职能/相对位置）；透视关系不含机位高低（焦距感、前后压缩用对比句式）；占画幅多少（tag 完全说不了，想强调腿部靠这个）；运动的进行中状态（tag 只能说 `running`，说不出停在哪一瞬；否定句排除静止感很有效）；光影叙事（主光源+第二光源+投影形状——方向句要配一个方向 tag 兜底）；场景物件的整体性（清单式罗列后补一句整体性要求，防止糊成抽象纹理）。

**句法约定**：主语单人用 `The character`；时态现在时/现在进行时；一段一个职能、段间空行分段（不用 `|` 代替空行）；关键独立物件拎出来单独做 tag 放前部（`transparent umbrella, wooden bench` 优于 `holding a transparent umbrella on a wooden bench`）；英文为主——很长、结构复杂或英文难准确表达的句子直接写中文，有歧义的概念用中文钉死。

## 语义冲突检查表

按"同一主体/同一画面"判归属：

- **视线方向**：`looking back`（回头）和 `closed eyes`（闭眼）不是方向可叠加；**多角色互看只写 `looking at another` 一个**——`looking up, looking down, looking at another` 全摇摆是错的（高低差进句子）。
- **机位**：垂直机位 `from below`/`from above` 互斥，但可与一个水平机位叠加（`from below, from side` 合法；`from behind, from side` 不合法）。
- **取景距离**：`wide shot` 说镜头退多远，可与 `full body` 叠加。
- **体位**：多角色例外——一人站一人蹲时两个都写，靠句子说清谁是谁。
- **`close up` 与 `close-up`** 是同一个词的两种写法，挑一个。

## 已知陷阱

- **`from below` 重手**：`from below` + `foot focus` + `feet out of frame` 三个一起会把姿势 tag 整个盖过去，人变成近乎躺倒。要低机位又保姿势，只留 `from below`。
- **景深词**：`depth of field` / `bokeh` 是浅景深虚化，用于特写人像；大场景需要全景清晰，用了反而压掉远景细节。
- **服装状态词先查中文释义**（误伤是换衣服不是效果弱）：`loose socks`＝堆堆袜（粗针棉袜）≠丝袜滑落；`single thighhigh`＝只穿了一只≠一只滑下来；`thighhighs pull`＝拉扯动作≠已滑落状态。**形制归 tag，不对称与位置归句子**。
- **V5 透明三词条**：`transparent background`（左下角透明背景同效）；`has alpha` 加在光效/粒子词条之后；`alpha transparency` 让物体真透空走 alpha 通道（做素材用，完整画面里画透明伞写 `transparent umbrella`）。

## 权重语法体系（按模型速查）

| 体系 | 语法 | 有效区间与细节 |
|---|---|---|
| **NAI**（V4.5/V5） | `1.2::tag::` 数值权重（`{}`/`[]` 旧语法只读不写） | 常用 1.3–1.8（V4.5 需 3.0–4.0 等效）；三个语法坑（`::` 未闭合 / 数字结尾炸串 / 加权即召回）、负权与打包加权见 models.md 的 NovelAI 章 §权重语法（权威） |
| **SD / SDXL / NoobAI / Illustrious** | `(tag)`≈×1.1、`(tag:1.3)` 精确、`[tag]`≈×0.9 | A1111 语法；`\/` 转义字面括号；进阶语法（AND/交替/步数切换）与分隔符强度梯度见 models.md §SD 系 |
| **Anima** | `(tag:权重)` | 阈值高于 SDXL：1.5 起步、强强调 `(chibi:2)` 级别；详见 models.md §Anima |

- **NAI 与 SD 括号语法相反**，跨平台必须转换，不直接照搬（换算表与**越界权重的处理**见 convert.md）。
- 用户给定权重的细节（如 OC 库标注 `(forehead:0.8)`）原样保留，语法按目标平台转换。

## 多人机制（→ models.md 权威）

多人语法是模型专有机制，**完整规则权威在 models.md**：NAI 的 `Character N:` 字段全套（角色栏分工、人数 tag 唯一性、施受前缀、句子主语两分工、接触点归属、第三人规则、串味三件套）见 models.md 的 NovelAI 章 §多人机制（Character N: 字段）【权威】；SD 的 BREAK 分区（Regional Prompter）见 models.md §SD 系。多人场景**必读对应小节再动笔**。

通用判据两条：人数 tag（`1girl`/`2girls`）是构图第一锚点、只在主提示词最前出现一次；多人防串位靠句子写死归属，不靠堆权重。

## 画中文字（引号法）

- 用英文双引号把文字直接写在自然语言里并放在对应位置：`the words "博士的宠物" written on her left thigh`。
- 搭配标签：`text, english text`（英文）/ `speech bubble`（头顶气泡）/ `body writing`（身上写字）。
- **位置双维描述写死**：身体部位 + 画面构图部位，如 `on her left thigh, at the lower right of the frame`、`inside a speech bubble above her head, in the upper center of the image`；多段文字各带完整位置描述。
- 符号可混排（♡、…、！等均能渲染）；短句可靠，长段会糊。
- NAI 支持英文、日文、中文，日文可用半中括号 `「」`（容量限制见 models.md §容量）。
- **不要使用 `Text: ` 语法**——手动块会关闭文字自动功能，且实测会把 "Text:" 字样本身渲染进画面。

## SD 进阶语法（→ models.md 权威）

`(a AND b)`、交替提示、步数切换、管道切换、OR 随机等进阶语法，及分隔符强度梯度（`,` < `.` < `BREAK`），权威版本见 models.md §SD 系——仅在目标环境确认支持时使用。

## 画面组织六意识

1. **摄影意识**：用光线与景深组织画面；先决定性质光，再叠加方向、颜色、环境。
2. **表情一致**：用一致的表情传达情绪；情感场景的灯光和颜色主题要和表情配套（如病娇 = 表情组 + `purple light, purple screen, backlighting, purple theme`）。
3. **物理意识**：检查重力、接触面与力的方向；复杂姿势的接触和受力说得清。
4. **叙事意识**：用可见道具和痕迹叙事（`holding tray, omelette, id card` = 在努力做好女仆但编号仍在）。
5. **协同意识**：检查标签组合是否协同；好的组合是压缩信息（`dappled sunlight` 同时传达光线/环境/时间/氛围）。
6. **留白意识**：锁定核心，给非关键细节留白；姿势本身能暗示角度时不机械指定镜头。

## 性质光（互斥）

一个提示词里只能出现一种性质光，混用会脏面：

| 性质 | 标签 | 适用 | 代价 |
|---|---|---|---|
| 硬光 | `hard lighting`（搭档 `side lighting`） | 突出主体、紧迫氛围、电影肖像 | 皮肤材质下降 |
| 软光 | `soft lighting` / `diffused lighting`（搭档 `ambient light`） | 万能默认光——不加光影标签就是软光；厚涂/油画/全景 | 平淡 |
| 酷烈光 | `harsh lighting`（搭档 `extremely high contrast`） | 疯狂氛围、废土、末世 | 对模型容受要求极高 |

有风格标签时光影标签需加权（1.2–1.5）；`dappled sunlight` 是自然的软光变体，不与默认光冲突。

## 角色处理

### OC

- **按视线路径拆散**：眼睛跟表情走、头发跟姿势走、体型跟剪影走；整块粘贴 = 告诉模型「同等重要」= 失焦。
- **辨识特征全部保留**：打散只是位置重排，每个辨识特征（发色、瞳色、发型、体型、种族特征）都要写进标签。省略 = 模型随机填充 = 角色变成别人。
- **弱权重细节不省略**：带权重标注的辨识细节（`(forehead:0.8)`）同样必写，权重值保留。
- **碎发类细节写位置**：`stray hair strands` 无位置限定容易被画到脸/嘴边，要么写位置限定（`hair strands on shoulders`）要么删掉。
- 服装仅参考，按画面主题重新适配；标签只翻译视觉，背景故事留给小说。
- **颜色是人格**：身份在轮廓和关键配件，人格在颜色——换调色盘就换了一个人。
- **一个不可忘记的视觉锚点**：最好的角色设计有一个让人一秒记住的东西；**反差制造记忆点**（硬汉打手 + 嘴里叼着鲷鱼烧）。
- **最小可行角色**：减法 > 加法，只留下去掉就不是「她」的那几个。

### IP 角色（查证链）

1. **先查证后动笔**：本地角色库 → WebSearch 官方设定/wiki/标签页 → 都不可用则停止并向用户要参考图或外貌描述。
2. **锚定角色词**：最终标签必须包含 `角色名 (作品名)` 标准角色标签 + 作品系列标签；角色词不许省略或替换成泛化描述。
3. 查证到的外貌特征仍按视线路径拆散融入，辨识特征一个不能少。
4. 聚焦人物本身：以人物的外貌、服装、表情、姿势为主体，不写武器弹药等外物（用户明确要求除外）。

## 拼写规范

- 惯用拼写：`1girl` 不是 `one girl`；`twintails` 不是 `twin tails`；`thighhighs` 一个词；`looking at viewer`、`holding umbrella` 等 Danbooru 惯用短语。
- 拿不准时改用更基础的标签（如 `watercolor (medium)` 拿不准就写 `watercolor`）。
- 避免堆同义标签（`smile` 与 `grin` 二选一）——但同一对象的不同动作/形态/材质可协同描述。
- 画风 = 画师 + 视觉效果 + 主题色调配，不是画师名堆砌；「概念污染」是工具：作品名当风格、游戏 CG 当风格、画师名当风格（用户点名时才用画师）。

## 服装片段写法（换装/服装设计类交付）

用户要"一件服装的描述"（换装方案、服装设定、OC 衣柜）时，交付的是**片段**不是完整画面提示词：

- **片段交付边界**：不含人数、姿势、镜头、场景、质量词、UC——只交服装本身；成品一个代码块。
- **视觉意图九项清单**（写全一件服装的查漏序）：原型（这是什么类别的衣服）→ 轮廓（整体剪影）→ 领与袖 → 层次（内外穿了几层）→ 腰以下 → 腿与鞋 → 材质 → 标志性配件 → 不对称与佩戴关系。
- **部件一次定义**：颜色、材质、状态并入该部件的同一条描述（`white frilled blouse`），不拆成三个孤立 tag 再靠读者拼装。
- **标签/句子分工**：可枚举属性落 tag；穿脱关系与层次声明落句子，关系句以**部件**为主语（"the open cardigan hangs off one shoulder"），不用 "she wears..." 起句。
- **联动改写**：用户在成品上换一件服装时，只动服装组——被替换件连带的状态词（露点、勒肉、湿透）逐项检查同步。
