# 法典配方库使用指南（codex）

`database/nsfw/codex/` 是一个"**场景 → 成品 tag 配方**"的大型实例库：约 6,900 条完整配方，按场景/体位/服饰/组件/系列切成 101 个数据文件。每条配方 = 中文场景标题行 + 成品 tag 行（含数值权重与 Character N: 多人字段）。它是实证基准：写标签流成人提示词时，先检索相似场景的现成配方做基底，再按用户需求改编——比从零拼 tag 快且稳。

## 基准语法

配方已统一为 **NAI 数值基准语法**：

- 权重：`1.2::tag::`（作用到 `::` 为止）；负权重 `-1::tag::`；源数据中的 `{{}}`/`[[]]` 层级已按每层 ×1.05/×0.95 换算为数值。**读到超出 models.md 声明区间的值时按 convert.md §越界权重的处理**——不原样迁移
- 多人：`Character 1:` / `Character 2:` 字段（源数据 `char1:` 已规范化）。配方中写在 `Character N:` 行内的动作属 models.md §多人机制 例外 1（施受前缀）形态或例外 2（该角色自己的动作），不是「动作全进角色栏」；跨模型迁移时按权威条重排
- `【】`是占位符：源数据约定"请于【】处添加角色与画风的 tag"——使用配方时在此填入用户的角色/画风，不填则删除占位符
- 拼写已修正明显 typo；个别源数据畸形（未闭合括号等按最优解释修复，无法修复的保留原样）

## 使用流程

1. **检索**：按场景关键词 grep（先解析绝对路径）：

```bash
# 按中文场景标题检索（跨全部章节）
grep -rn "骑乘" "<ABS>/codex/positions/cowgirl.md"
# 按英文tag反查哪些配方用了它
grep -rln "asphyxiation" "<ABS>/codex/" --include="*.md"
# 定位文件后通读候选条目，选1-3条最接近需求的
```

2. **选基底**：选 1-3 条最接近用户需求的配方。
3. **按目标模型适配**（详见 convert.md 权重换算与 models.md）：
   - **NovelAI**：直接使用；权重如落在 1.1–1.3 无感区按需上调至 1.3–1.8
   - **SD / NoobAI / Illustrious**：`1.2::tag::` → `(tag:1.2)`；Character 字段 → BREAK 分区；拼写不变
   - **Anima**：数值按其阈值重定标（1.5 起步）；artist 加 `@`；`(reverse:1999)` 类消歧括号转义
   - **自然语言流**：整条改写为连贯句子（权重转措辞强调），见 nl-flow.md
4. **改编**：替换角色（用户角色 tag + 【】处）、调整场景/服装为用户要求；**保留配方的构图/姿势/镜头骨架**——那是配方的价值所在。
5. **按输出契约交付**（SKILL.md §五）。

## 过滤与边界说明

- **未成年指向条目已在入库时物理排除**（整章与逐条两级过滤，含 shota/loli/child/toddler 等全部指向词）。检索结果中不应出现此类内容；若命中疑似条目，忽略并按底线丢弃该输入。
- **门控范围以 [database/MANIFEST.md](../../database/MANIFEST.md) §nsfw/codex/ 为准**：除 `gated/` 23 个文件外，`het-series/` 下的**胁迫强制（coercion）、偷窥（voyeurism）、宠物调教（pet-play）、调戏（teasing）** 四章与 `gated/` 同级受限，同样受 themes.md 门控——只有用户显式点名该主题时才展开。其余章节按 B 模式正常使用。
- 配方为历史实测积累：语法已归一，但具体出图效果随模型版本浮动——以当前会话用户的反馈为准微调。
