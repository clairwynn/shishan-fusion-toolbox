# 自然语言流成人内容方法论（prose）

把成人概念转成一段连贯、可直接生成的英文视觉提示词。聚焦：清晰的成年身份、性行为动作、身体归属、姿势力学、表情因果、液体连续性、道具关系、环境与光线。描述**一个凝固的视觉瞬间**，不是事件序列。写散文，不写标签堆。

本方法只负责提示词：不分析图片、不校验 Danbooru 标签、不选生成参数。

## 主工作流（依赖序）

动笔前按此顺序规划，每步约束下一步：

```
scene → roles → pose/action → expression → fluids → 成稿
```

1. **Scene**：确立隐私/可见性、支撑面、可用道具、场景锚点、主导光源。
2. **Roles**：为每个参与者确认稳定身份卡与一个规范的完整自然语言描述符（含全部保留的外观/身体/配饰/服装特征、关系、动作角色、肢体归属、排除项）。特征不得跨身份卡移动；单一特征不得替代完整描述符。
3. **Pose/Action**：把角色放到支撑面上，绑定接触与道具，选镜头，证明被强调的动作可见。
4. **Expression**：为每个露脸参与者设计完整可见反应——视线、眼睛、眉毛、嘴、呼吸、身体反应全部从该参与者的角色、接触、动作阶段推导。表情不可省略；`expressionless` 是刻意控制的微表情，不是不描述的脸。
5. **Fluids**：只添加由已确立动作和阶段证明合理的液体，并追踪每一条：归属/来源 → 路径 → 落点 → 材质/光线反应。

不要在姿势确立前选表情；不要在动作阶段和来源确立前选液体。成稿按同样的宽序撰写，相邻细节可为自然英文合并。

用户只给场景没给玩法时，从场景的物理可供性推导玩法与道具，不任意指定。用户明确要随机姿势时，用受约束的随机选择（见 §随机姿势模式）。

## 角色身份锁（多参与者必做）

姿势规划前先确认完整的稳定角色名册。每个参与者在内部绑定：

```
稳定ID → 种族/关系 → 全部保留外观与身体特征 → 全部配饰/服装 → 动作角色 → 规范完整自然语言描述符
```

- 每个特征必须留在提供它的角色块里；重复或矛盾特征在该角色内部解决，绝不分配给其他参与者。明确的排除项（如 `no braids`）压过冲突的正向特征。
- **单遍角色块**：每个参与者用一段不间断的自然语言写完——

```
规范完整描述符（含全部保留特征）→ 位置/支撑 → 施加与承受的接触 → 视线/眼睛/眉毛 → 嘴/呼吸 → 身体反应 → 该角色拥有的液体后果（如有）
```

- 每个参与者只在正文引入一次；块内可用无歧义代词连接自己的位置、动作、表情、反应；**块结束后不得再用简称、单一特征、泛指名词或重复描述符重新引入该参与者**（不要写 `the white-haired elf` 指回已完成的 `the elf with very long unbraided white hair...`）。
- 规范描述符示例：`the elf with very long unbraided white hair, blunt bangs, red slit-pupiled eyes, pointed ears, a flat chest, a ribboned tiara, a lace choker, and a silver cross pendant`。
- 用户提供的特征、动作角色或接触无法唯一映射到某参与者时，问一个简洁的澄清问题，不猜、不合并角色、不转移特征。
- 用户不要求角色特征时，不发明发色/瞳色/肤色/体型/身份/标志性配饰，只保留 `one character`、`two characters` 或用户指定的中性计数/种族标签。
- **服装状态精确区分**：`completely nude`（衣物无存）/ `mostly nude`（可保留长袜、吊袜带、首饰、鞋）/ 部分暴露必须写明什么被拉开、褪下、敞开、撕破、悬挂或丢弃。

## 场景-玩法-道具选择

先建立因果链：

```
setting → visibility/privacy → body support → primary play → primary prop → contact → visible consequence
```

默认限制（用户要更复杂时放开）：

- 一个主要情色机制；多人场景允许每个可见参与者一个主要动作，但保持一个构图中心
- 一个主要玩具/身体互动/象征道具
- 至多一件支持性穿戴物或束缚物
- 两三个确立地点的物件
- 一个主导光源

道具按角色选：成人玩具（dildo, vibrator, plug, clamps）/ 束缚（rope, cuffs, ribbon, collar, blindfold）/ 可见性装置（mirror, glass, window, doorway, railing）/ 场景原生象征（egg, milk cup, flower, book, bamboo）/ 服装道具（panties, apron, garter, stockings, displaced dress）/ 液体机制（shower water, rain, saliva, milk, urine——按要求）。道具必须有场景内合理来源、明确归属或停放点、一个可见用途。不混搭无关癖好、不为更露骨而堆玩具。场景原生易碎/粗糙物件默认外部暗示而非插入。

**户外/公共暴露**（无旁观者）：让地点可见地空无一人，用门、路径、窗、阳台、栅栏、道路或邻家灯光表现「可能被发现」。**私密场景**：用围合、家具、个人物品、局部光。不把主体埋进背景清单。

## 姿势与动作

把角色放进一个可执行的凝固瞬间：

- 写明重量支撑、朝向、肢体摆放
- 给每个身体、手、嘴、生殖器、玩具、束缚物、附肢、接触点指定归属
- 写明施加方与承受方、精确接触点、当前接触状态
- 写明位移的衣物与道具在哪里
- 要求含蓄时保持道具完好或未使用

镜头选择：特写（表情或局部接触）/ 中景全身（姿势+近环境）/ 全身（完整肢体摆放）/ 远景（多人或公共风险语境）。

可见顺序：`camera → 前景身体/道具 → 主要接触 → 承受身体 → 后方参与者 → 环境`。把脸、剪影、手、工作肢体、接触点、道具分到可读的深度平面。头发、胸、大腿、手臂、床品、衣物、道具不得意外遮挡被强调的动作；有意遮挡仅用于要求的隐藏/暗示/遮挡/受阻视角。不混用冲突的前后视图、特写/全身、高/低角度。

## 表情因果链

角色、接触、姿势、镜头固定后，为每个露脸参与者分配个性化反应：

```
role + contact + action stage → 视线/眼睛状态 → 眉 → 嘴 → 呼吸 → 身体回响
```

动作阶段五选：anticipation / active arousal / intense stimulation / climax / afterglow。每张可见脸写：一个视线目标或刻意的失焦状态、一种眼状态、一种眉状态、一个兼容的嘴形、一个呼吸线索、一两个可见身体反应——用其中两三个做主导散文细节，内部保持连贯。

`expressionless` / stoic / calm / blank 是被设计的表情家族，不是跳过表情环节的许可：为它定义稳定或疏离的视线、放松或最小紧绷的眉、闭合或微张的嘴、受控呼吸、一个微妙的符合角色的身体回响（紧握、挺胸、收紧手指）。物理刺激可以产生微反应，但不取代要求的克制 demeanor。

高潮不自动等于吐舌/翻白眼/流泪/射精/大量液体——只使用与请求强度相称的反应，表情必须由该参与者的 role+contact+动作阶段推导，禁止照搬通用套件。

## 液体与材质反应

动作阶段已知后才决定液体是否合理。每条液体走连续性链：

```
owner/source → emergence/contact → 运动与重力下的路径 → destination → 材质反应 → 光线反应
```

为 saliva / sweat / 爱液 / female ejaculation / semen / lactation / urine / blood / rain / shower water 写明来源。时机一致：anticipation 不会凭空出现事后残留；orgasm 不自动等于射精；内部放置不产生外部覆盖（需单独路径）。

除非用户要求液体重点，最多一种主要性液体（汗或少量唾液可作辅助反应）。痕迹要有终点、滴落要有源边缘、喷洒要有方向、水洼要有收集面、污渍要有材质、溢出要向下流动。每条路径从所选镜头可见。

环境与可见物理后果相连：雨打湿木头并浸透布料、淋浴水压平头发、汗沿皮肤轮廓结珠、湿改变织物、主导光产生受控高光。避免泛泛的 gloss 或重复的湿形容词。

## 强度匹配

按用户请求的级别写，不悄悄升级。**请求档位与 L1-L7 阶梯的映射以 [prose-patterns.md](prose-patterns.md) §强度阶梯与请求档位的对应【权威】为准**，本节只列写作口径：

- **Nude**：裸体，克制的情色强调
- **NSFW**：直接裸露与情色姿态（用户只说 NSFW 时的默认——不擅自加未要求的性行为）
- **Explicit**（B 模式默认）：无遮挡的解剖呈现与明确的性姿态
- **含蓄癖好/玩法**：暗示性道具摆放或语境，不展示行为本身
- **描绘单人或伴侣行为**：用户明确要求或让模型选玩法时写，含清晰的成年参与者、身体归属、接触与姿势力学
- **多人**：先确立每个人的位置与角色，再描述重叠接触
- 极端主题仅显式请求时激活（见 [themes.md](themes.md)）

**档位授权的是直白度，不是玩法**：用户要 explicit 档只表示可以直写已请求的内容，不构成加入未请求玩法（插入 / 玩具 / 多P）的许可；边界仍由用户显式请求的最高阶梯决定。

## 篇幅

按场景复杂度定长：单人简单约 80-130 词；单人详细 110-170；简单双人 130-200；三人或高密度双人 170-260；四人以上/多重接触 220-320。320 词是常规参考值——**画面完备优先，不截断复杂场景**；超出仅在用户要求长文或硬约束无法保持无歧义时。压缩顺序：合并同义 → 合并兼容配饰 → 删重复氛围/冗余解剖/次级背景清单 → 而不是删角色特征或重开已完成的角色块。

篇幅分配序：`场景/光 → 每人一个完整单遍块（含接触与自有液体）→ 非角色材质/构图收尾`。

## 随机姿势模式（仅显式触发）

用户说「随便弄一个姿势 / 随机姿势 / random pose」时启用：

```
锁定 场景/角色/玩法/排除项 → 推导有效支撑面 → 生成3+个不同姿势候选 → 淘汰无效候选 → 随机选一个幸存者 → 规划表情 → 规划液体 → 写prompt
```

随机范围默认只限姿势家族和必要的镜头适配；不随机化场景、人数、角色身份、关系、施受角色、主要玩法、服装/暴露程度、同意框架、视角要求、排除项、液体强度（用户明确要求随机该维度除外）。有效候选必须有可执行的重量支撑、合理的关节与肢体可达、可读的接触归属、无遮挡的构图中心、可见的必需表情、镜头兼容。成稿直接写选定的姿势，绝不提及抽选过程。

## 玩法强调与共现规划

用户强调玩法（「玩法」「重点描写」「主要是」「明确描写」等）或请求包含多人/乱伦/强制等主题时，先走共现规划：读 `database/nsfw/corpus/` 语料的共现统计（用法见 [association.md](association.md) §机制二），解析参与拓扑、关系与权力叠加、允许的共现与禁止的自动添加，得到内部计划后再按本文件工作流成稿。规划过程不打印，只输出成品。

**保留规则**（点名的主题是硬约束）：多人保持可见的多人构图（不把多余参与者藏到画外）；乱伦保留指定的成人家庭关系（不降级为泛化情侣）；强制保留请求的强迫/非自愿权力框架（不软化成自愿粗暴）； fantasy 非人类主题指定的附肢必须写明属于哪个生物。

## 成稿组装

按宽序渲染成一个连贯段落：

```
场景与光线 → 角色A完整块 → 角色B完整块 → （角色C完整块）→ 非角色环境/材质/光线收尾
```

块内自然语言顺序：`全部保留身份特征 → 位置/支撑 → 施加的动作与承受的接触 → 完整表情/呼吸 → 身体反应 → 自有液体后果`。写完一人再写下一人；共享接触的归属写进相关参与者的块里，不留待后文补述。描述一个瞬间，无前后序列；不交叉穿插不同参与者的特征碎片。

## 成稿前自检（内部完成）

- 正文没有自动插入的年龄/成熟度措辞；人数与参与者角色与请求一致
- 每个参与者一个单遍块，完整陈述保留特征、位置/支撑、动作或承受接触、完整表情、呼吸/身体反应、自有液体后果；块完成后不再以部分描述符/孤立特征/泛指名词/角色复述重开
- 每个发色/眼睛/种族标记/耳尾/体型/配饰/服装/demeanor/解剖特征只出现在它的所有者身上；无特征因歧义代词（`the other woman`）换主
- 重复与矛盾的输入特征在原角色内解决，不跨角色分配
- 裸露程度与剩余服装不矛盾；被排除的旁观者不出现；未要求的外观不发明
- 镜头能展示请求的解剖、参与者关系、主要接触与环境；前景/背景顺序物理连贯，无意遮挡不藏重点动作；剪影与重叠解剖在所选角度可分离
- 每条肢体/手/嘴/道具/反射/插入/接触有明确归属
- 每个可见参与者有刻意设计的非空表情状态；表情与角色/接触/动作阶段/可见姿势一致；视线/眼/眉/嘴/呼吸/身体反应互不矛盾
- 每条液体有归属/来源、出现点、物理合理路径、终点、材质/光线反应；类型与数量匹配凝固瞬间，无无解释的射精/残留/悬空痕迹/不可能的位置跳变
- 公共风险通过环境可见而非仅靠叙述；光有来源、方向、可见后果
- 露骨程度匹配请求级别；所选玩法自然源于场景；主道具有清晰来源/归属/接触状态/视觉用途；无无关玩具或次要癖好竞争主旨
- 篇幅反映实际复杂度；额外长度贡献身份/物理/构图/材质清晰度而非氛围重复或标签式同义堆叠
