# 联想引擎（仅 B 模式 · 仅生成任务）

触发条件：B 模式下的**生成**任务，且用户需求模糊（只给一个词/一个概念/「随便来点」）或用户明确要求联想/扩写/方案。反推与转换任务**不触发**本引擎。

流程：跑五机制 → 汇成 **3 套各自完整的方案** → 让用户选一套 → 按选中方案写成品。三套方案要真的不同（画面构思/玩法组合/强度侧重不同），不是同一方案的措辞变体。

每套方案的结构（内部规划用，呈现给用户时简洁列出）：

```
方案N：核心构思一句话
  画面要点（场景/姿势/构图/光线/情绪链）
  玩法组合（角色+接触+道具+强度）
```

## 机制一：主动画面构思

对模糊概念主动构思完整画面，而不是照字面直译：

- 内部先明确"这张图的灵魂是什么"——灵魂元素即第一个视觉锚点。
- 按 10 层要素清单逐层构思补全：主体人数 → 角色 → 场景 → 姿势动作 → 构图镜头 → 表情视线 → 服装状态 → 发色瞳色 → 风格 → 内容分级校验（10 层即 SKILL.md 工作流 A 的要素清单——同一画面要素体系的构思视图，层次以 SKILL.md 为权威）。
- 情绪定位先行：从五级梯度（害羞→发情→被压倒→高潮→崩溃）中选定情绪阶段，表情、灯光、颜色主题与之配套。
- 用反差与叙事制造记忆点：兽性特征配软糯情绪、日常上半身配激烈下半身（感觉遮断）、半遮半掩胜过全裸、静态痕迹讲故事。
- 环境是人格的外化：同一角色 + 不同环境 = 不同故事；构思时把环境当角色的另一半来选。

## 机制二：语料共现组合

`database/nsfw/corpus/` 存有玩法语料的共现统计（定位与格式见 MANIFEST）。规划玩法组合时：

1. 从用户需求中解析**参与拓扑**（solo/双人/多人）、**关系与权力叠加**（平等/支配/服从属普通叠加层；**家庭及其乱伦、NTR 或出轨、非自愿或强迫**属极端主题，只有用户点名该主题时才能叠加——完整清单见 themes.md）、**身体行为核心**。
2. 查语料共现，看与核心行为高频共现的场景叠加、道具、液体、表情元素，作为方案的可选搭配（共现指导可选添加，但**绝不覆盖用户的明确措辞**，也**不自动添加极端主题**）。
3. 组合成 2-3 个玩法方案：每个方案锁定一套「角色注册表 → 具体玩法 → 姿势 → 接触图 → 表情图 → 液体连续性图 → 镜头构图」。
4. 保留规则：用户点名的主题是硬约束，共现结果只做补充，不做改写（多人保持可见多人、强制保持非自愿框架、兽交保持真实动物）。

## 机制三：标签共现矩阵联想

`database/tags/cooccurrence.csv`（52MB，191万行共现对，格式 `tag_a,tag_b,count`）可用于标签流方案的搭配联想。查询（先解析绝对路径）：

```bash
# 查某标签的高频共现伙伴（按count降序思路：count列很大，用sort）
grep -P "^\Qsolo\E," "<ABS>/cooccurrence.csv" | head -30

# 反向：谁最常与目标标签共现
grep -P ",\Qpaizuri\E," "<ABS>/cooccurrence.csv" | head -30
```

用法：

- 用户给出核心标签/概念时，查它的共现伙伴，把高频且画面合理的组合纳入方案（共现是统计关联，不是质量保证——取用前过一遍画面合理性判断）。
- 用于补齐「这类画面通常还要什么」：姿势搭配、构图惯例、配套状态标签。
- 矩阵是 Danbooru 全量数据，含普通向内容——成人场景联想时先过滤分级不符的伙伴。

## 机制四：进阶技巧库调用

从 [tags-techniques.md](tags-techniques.md) 与 [prose-method.md](prose-method.md) 调用成熟的技法模块拼进方案：

- **万能尾缀三套**：发情氛围 / 高潮失神 / 被发现羞耻——按情绪阶段套用。
- **化学反应组合库**：冲击力、弥漫情欲、皮肤质感、透明感、无意识感、内外同展、导演裁切、湿透感——按画面重点选 1-2 组。
- **施受定向**：source#/target#/mutual# 精确指定双人动作方向。
- **非直觉技法**：层级裁切、透视截面、差分多视图、直播伪截图、场景拘束、感官剥夺分层——需要特殊构图/叙事时选用。
- **道具叙事**：文字道具、衣物无人暗示、逃离叙事三层、NTR 道具——需要故事性时选用。
- **角色类型锚定**：伪娘/futa/NTR/人外/魅魔堕落等的精确锚定 tag 组合——涉及对应角色类型时直接取用。
- prose 侧：身份卡+单遍块、表情因果链、液体连续性链——自然语言流方案按 prose-method 规划。

## 机制五：法典配方检索

`database/nsfw/codex/` 存有约 6,900 条"场景 → 成品 tag 配方"（用法详见 [codex-guide.md](codex-guide.md)）。配方是实证基准——比统计联想更能直接落地：

1. 从用户需求提炼场景关键词（体位/场景/服饰/视角），grep 检索 codex 对应目录：

```bash
grep -rn "关键词" "<ABS>/codex/positions/" | head -10
grep -rln "英文tag" "<ABS>/codex/" --include="*.md"
```

2. 命中相似场景配方 → 作为方案基底：保留其构图/姿势/镜头骨架，替换角色、场景、服装为用户要求。
3. 未命中 → 退回机制一（主动构思）+ 机制二（语料共现）组合方案。
4. gated/ 目录受 themes.md 门控：只有用户显式点名该主题时才检索使用。
5. 跨模型需求按 codex-guide.md 的适配规则转换（SD/Anima/自然语言流）。

## 输出规则回顾

1. 三套方案，各自完整、真实不同。
2. **先选再写**：呈现方案等用户选定，再按选中方案产出成品提示词（成品按输出契约：代码块、无来源标注）。
3. 用户对方案的修改意见直接吸收进成品，不需要再走一轮方案确认。
4. 普通明确的需求（用户已给全要素）不走联想引擎，直接按工作流 A 生成。
