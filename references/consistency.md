# 跨图一致性锁定（Consistency）

跨图、跨镜、跨批次保持一致，靠的不是模型记性，是**显式声明的不变量**。本文给出三层锚点、四条实现路径（不变量声明 / character sheet 工作流 / NAI V5 角色栏 / prose 身份卡）与漂移诊断。

## 一、三层锚点

| 层 | 要锁的东西 | 手段 |
|---|---|---|
| **角色** | 脸型五官、发型发色、瞳色、体型、肤色、服装、配饰、道具 | character sheet 参考图 + 身份不变量声明 |
| **场景** | 空间结构、家具位置、光线方向、色调、天气、时间 | 场景参考图 + 空间锚点描述 |
| **风格** | 媒介、渲染方式、色调、颗粒、笔触、后期 | 风格锚点词 + 参考图 |

**规则：能锁的尽量锁，只把真正要变的写成变量。变量越少，一致性越高。**

## 二、不变量声明（通用手段，任何形态都要写）

跨图 / 跨镜任务在提示词里显式声明（格式模板）：

```
以下保持不变：主体脸部与五官、发型发色、体型、服装与配饰、构图/裁切、
光线方向与软硬、色调与饱和度、背景结构与元素、整体风格与媒介。

只改变：<明确列出的变量>。

不要添加或移除：<主目标 / 关键元素>。
```

- **声明不变量优先于堆负面词**：不变量是主锁，负面词是扫尾。
- 多主体场景加计数约束：`恰好 [N] 个主要人物/目标` + `不要增加或减少主目标`；超过 6 个目标用分组、手势、眼神与节拍代替逐人描写；背景群众只在被要求时存在且保持次要。
- 图生图 / 编辑任务同一原则：明确唯一改动目标，其余全部写进「保持完全一致」清单，不一次改三件事。

## 三、Character Sheet 三视图工作流

同一角色要出现在多张图 / 多个镜头时，把角色工作表作为第一个提示词交付物。**一表一角色**，多角色各写各的，不并表。

**下游顺序**（告知用户的用法）：

```
1. 生成角色工作表（character sheet）
2. 用工作表作参考，生成首个场景静帧
3. 从场景静帧派生后续镜头（图生图 / 图生视频）
```

**先确认缺失项**（问齐再动笔，逐个确认）：

1. 视觉风格：写实身份表 / 电影写实 / 二次元 / 3D / 厚涂 / 美漫
2. 角色基础：年龄段、性别呈现、族裔或肤色、体型、身高感
3. 面部锚点：发型、发色、脸型五官、瞳色、显著特征
4. 服装锚点：上衣、外套、鞋、配饰、随身道具
5. 表的范围：仅三视图 / 三视图 + 表情行 / 完整制作表
6. 用途：通用参考 / 场景静帧 / 直接用于后续派生

用户已有角色图时，**把那张图当身份锚点围绕它描述，不重新发明角色**。

**写作顺序**：声明这是角色工作表 / 三视图 → 用具体视觉语言定义身份 → 锁定服装与轮廓（silhouette）→ 指定视图与分格 → 指定跨分格同一性渲染约束（`the same character with identical face, hairstyle, body proportions, outfit and color scheme across all panels`）→ 指定背景与呈现（纯色背景、均匀布光）。自然语言流完整写法见 [nl-flow.md](nl-flow.md) §角色工作表（多视图）。

**默认分格**：全身正面、全身 3/4、侧脸、背面；可选表情行、手部姿态、道具特写、面料配饰细节标注。

**写实身份表模式**（真人感 / 纪实风 / 基于上传肖像建表）：

- 保留面部不对称、年龄线索、皮肤纹理与小瑕疵，不要平均成通用美颜模。
- 姿态自然不死板对称；目标是「同一个人被反复拍摄」，不是「重新设计的数字资产」。
- 少用负面约束，只在压制典型失败（合成 3D 感、过度风格化）时用。

## 四、NAI 路径

### Character N: 栏锁外貌

- 每个角色一个 Character N: 栏；**角色栏只写外貌与服装**，动作、表情、镜头、场景留主串——这是减少角色特征串色的机制。**动作入栏的两条硬边界例外**（施受前缀、第三人动作）见 [models.md](models.md) §多人机制【权威】。
- **版权角色极简触发**：角色栏写标准角色词（`角色名 (作品名)`）与作品系列标签即可触发训练样貌——模型自带角色知识，**不凭印象补写默认外貌**；用户明确指定的服装与外观改动逐项保留。角色词写法与查证链见 [tag-flow.md](tag-flow.md) §角色处理。
- **OC 锚点全保留**：发色、发型、瞳色、体型、肤色、种族特征与标志性配饰一个不能少——省略即随机填充，角色就变成别人。按视线路径拆散落位：拆散是位置重排不是删减（拆法见 [tag-flow.md](tag-flow.md) §角色处理）。
- 人数 tag 只在主串最前出现一次，角色栏写不带数字的 `girl` / `boy`。

### V5 与 V4.5 的差异（两版机制不同，别混用）

| 项 | V5 | V4.5 |
|---|---|---|
| 位置机制 | **Custom position 自由画布**：框顺序 + 坐标定位，Y 坐标 = 深度 | **5×5 网格 Position**（旧机制）：只能锁「同格位」，**不锁坐标**——跨图保持的是「第 2 行第 3 列」这类格位，不是精确坐标 |
| 权重感知 | 数值区间 1.0–2.0，1.3–1.8 最常用 | **感知更钝，需 3.0–4.0 才有 V5 的 1.3–1.8 等效强度** |
| `{}` / `[]` 旧语法 | 只读不写 | 只读不写 |

- **V4.5 锁位置时不要承诺像素级一致**——5×5 网格只能保证「大致同一区域」。用户要求严格同位时，如实说明 V4.5 的机制限制。
- **V4.5 跨图锁外观时把权重提到 3.0–4.0 等效区间**，否则跨图一致性弱于 V5（这是 V4.5 的模型特性，不是本 skill 的写法偏好）。
- V3 及以下：`|` 是 prompt mixing 不能用于多人，`{{}}`/`[[]]` 为旧权重语法——只识读，产出一律按现行语法写。

### Custom position 锁位置（V5）

- V5 自由画布：Character N: 框的顺序与 Custom position 决定角色位置；**Y 坐标 = 深度**（下 = 近，可只露局部、占画幅最大；上 = 远，明显缩小）。
- 跨图保持同一站位构图时，把每个角色的 position 坐标当作不变量：**坐标逐图原样复用**，位置不动。
- 角色之间不要靠得太近，否则坏图；控件定层次、句子描述层次，两个一起上。

## 五、prose 路径（自然语言流）

自然语言流没有角色栏，一致性靠**身份卡 + 单遍角色块**：

- **身份卡**：每个角色在内部绑定一张稳定身份卡——一段规范完整的自然语言描述符，含全部保留特征（外貌、身体、配饰、服装）。特征不跨卡移动、不在卡内自相矛盾；明确的排除项（如 `no braids`）压过冲突的正向特征。
- **单遍角色块**：每个角色在正文用一段不间断的自然语言写完（规范描述符 → 位置 → 动作 → 视线表情 → 反应），**块结束后不再用简称、单一特征、泛指名词重新引入该角色**。
- 该方法产自多参与者成人场景（完整规则见 [nsfw/prose-method.md](nsfw/prose-method.md) §角色身份锁），但其身份锁思想适用于**一切多角色自然语言流场景**：规范描述符 + 单遍引入 + 特征不串卡。
- 用户未要求角色特征时，不发明发色、瞳色、标志性配饰，保留中性计数即可。

## 六、负面词不承担一致性

- **负面词锁不住身份**：UC / negative 里排除「别人的脸」挡不住正向描述缺失导致的随机填充。一致性由正向不变量 + 参考图承担，负面词只做扫尾（压典型失败模式，如写实表的合成 3D 感）。
- 多人串味时三件配合，主次分明：句子写死归属（主锁）+ 该角色 UC 排除对方特征（扫尾）+ 检查人数 tag 没在角色栏重复（排错）。负面词定制按 [negative.md](negative.md)。

## 七、漂移诊断

第二张图换脸 / 换服装时，按顺序排查：

1. **身份锚点在不在**：只有文字描述、没有 character sheet 或参考图 → 先补表再继续。
2. **描述完不完整**：OC 有没有辨识特征被省略；描述符是否规范完整；有没有被简称、泛指名词复述打散。
3. **服装粒度够不够**：描述太笼统 → 锁轮廓与关键单品（领型、长度、材质、颜色）。
4. **光线与风格进没进不变量**：主光方向、光比、风格锚点词是否逐图逐字复用。
5. **计数与空间写死没有**：恰好 N 个 + 不得增减；前中后景关键结构与相对位置。
6. **NAI 专属检查**：角色栏是否混入动作表情、人数 tag 是否重复、position 坐标是否逐图一致。

其余常见漂移：

| 症状 | 原因 | 修法 |
|---|---|---|
| 角色像美颜模板 | 缺不对称与瑕疵描述 | 补面部不对称、年龄线索、皮肤纹理 |
| 主目标数量变了 | 无计数约束 | 补「恰好 N 个 + 不得增减」 |
| 场景结构飘移 | 无空间锚点 | 写死前中后景结构与相对位置 |
