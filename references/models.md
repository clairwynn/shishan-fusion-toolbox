## 统一裁决（所有模型适用，优先级高于各模型官方惯例）

- **质量前缀一律不加**：masterpiece、best quality、very aesthetic、no text、high quality、4k、8k 等质量词，任何模型都不写——包括 NovelAI 的「质量尾」；用户明确要求按官方完整格式时才补。
- **前缀豁免**：Anima 的数据集标签（`ye-pop` / `deviantart`）置于人数之前，官方格式必需——是「人数 tag 恒在最前」红线的唯一例外。
- **年代词全部不写**：`year 2025`、`newest`、`recent`、`mid`、`early`、`old` 一律不写（包括 Anima 官方支持的年代词）。
- **拼写与权重**：标签统一空格形态（`long hair` 不是 `long_hair`；**登记例外**：`score_*` 保留下划线、NewBie 的结构槽按该格式官方惯例用下划线——见 §NewBie）；默认一律不加权。
- **画师标签**：用户点名画师才写；Anima 下自动加 `@` 前缀。
- **负面词默认不给**：各模型的 UC / 负面基础串只作为「用户开口要时」的参考池，记录在各自章节；定制规则见 negative.md。
- **分级门控（内部判定，不写入提示词文本）**：A 模式限全年龄向——普通内容与泳装/内衣/浴巾等擦边均可写，更高一律归 B 模式；B 模式放开成人内容，默认按用户请求档位判定，用户指定其他档位时以用户为准。

## 组装顺序总则【权威】

全skill 的组装顺序以本节为准。各references 的顺序章节都是本总则在对应形态下的**展开**，冲突时以本节为准。

**通则（六段）**：`身份 → 主体属性 → 关系/动作 → 环境 → 观察视角 → 风格`

**标签流展开**：`[人数] → [角色] → [系列] → [@artist] → [主体特征] → [服装] → [动作姿势] → [场景] → [构图镜头] → [风格]`

**自然语言流**：nl-flow.md 的八段是本通则的**展开版**；本文件各模型节的「六层信息序」（主体与动作 → 外貌 → 服装/材质 → 场景氛围 → 镜头/光线 → 风格）是**压缩表述**，两者不是并列的两套排序。

### NAI 有意偏离官方顺序

NovelAI 官方主串顺序把**动作放在镜头之前**。本 skill **有意偏离**：统一为「动作在场景/镜头之后」。

- **理由**：动作进 `Character N:` 角色栏时，若主串同时有动作，角色栏会与主串的动作描述互相竞争，导致动作归属混乱与特征串色。动作后置让主串先建立「谁在做什么」的语境，角色栏专注于静态外观。
- **代价**：NAI 原生社区习惯的动作前置会略被打乱，但换来的是角色栏职责单一、更少串色。
- **适用范围**：仅本 skill 产出时；**读取用户给的原串时不重排**（转换的逐字冻结原则优先，见 convert.md）。

### 两条不许跨越的红线

1. **人数 tag恒在最前**——`1girl`/`2girls`/`1boy` 只在主串最前写一次，角色栏不再写带数字的同义 tag（见 §NovelAI 多人机制）。
2. **质量尾不存在**——不要在任何模型的顺序骨架里保留「质量尾」占位。本 skill 不写质量前缀（见 §统一裁决），写它等于暗示它可用。

## NovelAI（V4.5 / V5）

同时训练了标签与自然语言字幕，标签流、自然语言流、混合流三种形态皆可。写法上最自由、专有规则也最多的模型，逐项遵守以下细则。

### 输入形态

- **三形态皆可**：词组块+句子块（默认）、词组混入句子、纯句子。
- **判据**：句子写关系更准，词组写离散事实更准。V5 不在乎某一块是 tag 还是句子——按内容选表达，不按形态凑格式。
- 句子按 tag-flow.md 的句法约定写：主语明确、现在时、一段一个职能、段间空行分段。
- 混合写法的穿插策略见 hybrid-flow.md。

### 主串组装顺序

按 §组装顺序总则 的标签流展开（动作在场景/镜头之后）：

```
人数 → 外貌 → 服装 → 表情 → 场景/背景 → 镜头 → 动作
```

- 人数 tag（`1girl`/`2girls`/`1boy`/`1other`…）放最前。
- 场景/背景插在镜头之前。
- 本skill 不写质量尾——官方惯例把质量尾放最末，按统一裁决整项省略，不在骨架里保留占位。
- **靠前的成分影响力更大**：灵魂元素尽量前置。

### 权重语法

- **数值语法**：`1.2::tag::`——权重作用于该 tag，到闭合的 `::` 为止。
- 区间 1.0–2.0 非线性变化明显，**1.3–1.8 最常用**；常见增强 1.1–1.5、强增强 ×2，弱化 0.4–0.9，负权 −1 到 −5。默认不加权，确需强调核心概念时再上。**换算到其他模型时、以及读到超出本区间的数值时怎么办→ convert.md §越界权重的处理**（本节只管本模型产出时的区间判定）。
- **`{}` / `[]` 旧语法只读不写**：读旧串时按 `{tag}`≈×1.05/层、`[tag]`≈×0.95/层理解；自己写一律数值语法。`::` 也可以闭合任何未配平的 `{` `[`。
- **三个语法坑**：
  - `::` 未闭合会作用到之后所有 tag 直到结尾——不是只影响一个词。
  - **数字结尾炸串**：tag 以数字结尾又紧跟 `::` 时会被解析成权重——`na_tarapisu153::` 被解析成权重 153，整条提示词炸掉。写成 `na_tarapisu153, ::`（加逗号比加空格安全）。
  - **加权即召回**：服饰/物件词绑着训练集常见构图，加权可能连带出预期外的搭配（不只是加强该物）。
- **负权重属进阶**：`-1::tag::`、`-2::tag::`。本图不要的具体元素写成正面负权重，放在主串最后一行——不进 UC。

### 多人机制（Character N: 字段）【权威】

本节是**跨模型总则**：任何提供角色栏/角色分区的模型（NAI、SD 的 BREAK + Regional Prompter 等）都按此裁决。各 references 出现相反表述时以本节为准。

- **角色栏只管外貌和服装**：每个角色一个 `Character N:` 字段，角色栏只写该角色的外貌/服装；动作、表情、镜头、场景、背景默认留在主提示词——这是减少角色特征串色的机制。
- **人数 tag 只在主串最前写一次**：`2girls` 写主串，角色栏只写不带数字的 `girl`/`boy`/`other`。`2girls` + 角色栏各写 `1girl` = 人数翻车。
- **`solo` 用于单人图**；多人图中要聚焦一人写 `2girls, solo focus`（`solo` 修饰的是「聚焦」而非「人数」，与`2girls` 并存不冲突）。动物与人同框去掉 `solo`，动物用普通名词（`black cat`）写进画面。
- **框的顺序决定画面位置**（从上到下、从左到右）；**Custom position 画布的 Y 坐标被解释成深度**：下=近（可只露局部、占画幅最大），上=远（明显缩小）。控件定层次、句子描述层次，两个一起上；角色之间不要靠得太近，否则坏图。
- 官方最多 22 个角色——不沿用 V4 的「六人上限」与 5×5 网格旧限制。
- **每个角色段只写该角色**，减少信息泄漏；基础段只写场景/风格/环境。
- **编号与名字一一对应**：`Character 1` / `Character 2`，不写 Character A/B；用户指定了对应关系就照写，不自己重排。
- **句子主语两分工**：归属/位置句用 `Character 1/2/3`；交互动作句（谁对谁做什么）用**外观短语**指认（`the girl in the beige coat hands the cup to the girl with headphones`）——编号绑外观是准的、绑职能不准。两种句子都不用角色真名当主语；只复用辨认必需的简短锚点，不把整套外观抄进句子。
- **接触点必须有主人**：每一个接触、每一件共用道具都说清是谁的手、碰到谁的哪里（✅ `Character 1 presses her palm down on the back of Character 2's hand.` ❌ `Their hands are touching.`）；同一块画面出现三只手时补一句「每只手都清楚地连在自己主人身上」。

#### 动作进角色栏的两条硬边界例外

「动作留主串」有且只有两条通道可以把动作写进角色栏，其余动作一律留主串：

- **例外 1 · 施受前缀**：`source#{动作}`（发起）/ `target#{动作}`（承受）/ `mutual#{动作}`（互相）挂进对应角色栏——**这是动作入栏的唯一合法通道**。前缀表示**动作方向**，不是角色身份（`female#hug`、`char1#hug`、`left#hug` 都无效）；同一角色栏可同时挂 `target#` 与 `source#`（链式交互），视线用 `looking at target`。表情词只有跟着前缀标施受气质时才进角色栏（如 `source#teasing, smirk`），没挂前缀时表情回主提示词。
- **例外 2 · 第三人动作**：主交互之外的角色，她自己的动作写进她自己的前缀或 tag，句子只补她与主交互的关系——她不属于主串动作的施受方，硬塞主串会导致归属不明。

**为什么不开更多口子**：同一动作同时出现在角色栏与主串，两处会互相竞争与污染，角色特征串色与动作归属漂移都源于此。表情词同理：只有跟着前缀标施受气质时才入栏，否则留主串。
- **职能归属**：没把握就别分配——少写一句不会错，写反了整张图都怪；把场合写清楚模型会按先验分配。确有把握时写死：`"The microphone belongs only to Character 1."`
- **串味三件套**：句子写死归属 + 对方特征进该角色 UC 排除 + 人数 tag 查重（角色栏不得重复）。
- 存在任何角色面板时 `|` 语法被禁用，二者不能混用；旧式 `|` 分隔串（`2girls, 场景 | girl, 特征A | girl, 特征B`）**只读不写**——读旧串理解即可，数量词放基础段、角色段用单数；V3 及以下 `|` 是 prompt mixing，不能用于多人。

### 画中文字（NAI 特有项）

引号法通用写法（引号+载体+位置双维、搭配标签兜底、禁用 `Text:` 语法及原因）的权威版本见 [tag-flow.md](tag-flow.md) §画中文字 。NAI 特有：

- 支持英文、日文、中文；日文可用半中括号 `「」`。
- 多条文本各写清归属与位置；字符容量限制见 §容量。

### 角色栏拼写

- 角色名用 Danbooru 英文/罗马音，**只认 ASCII，中文名无效**。
- 『姓氏 名字』空格分隔、姓在前。
- 皮肤/异色外观的限定词写在角色名与作品名之间的括号里。
- **版权角色极简触发**：角色栏只写角色名即可触发训练样貌——不凭印象补写默认服装/发型（主串里的版权角色查证规则见 tag-flow.md）。
- **OC 相反**：样貌锚点一个不许精简，全部写进角色栏。

### 语义冲突（实测）

视线摇摆、机位互斥、`from below` 重手组合、景深词误用等实测冲突与陷阱，权威汇总见 [tag-flow.md](tag-flow.md) §语义冲突检查表、§已知陷阱——NAI 无额外独有项，按那份清单执行。

### V5 功能开关

- `low complexity` / `medium complexity` / `high complexity` / `ultra complexity`、`transparent background`、`has alpha`、`alpha transparency`、`depthness`。
- `has alpha` 加在光效/粒子词条之后；`alpha transparency` 让物体真透空走 alpha 通道（完整画面里的透明伞写 `transparent umbrella`）。
- 功能开关不是质量尾，**默认不加**——用户点名要对应功能（透明背景、出素材等）才写。

### UC 基础串（用户要负面词时的参考池）

```
lowres, artistic error, film grain, scan artifacts, worst quality, bad quality, jpeg artifacts, very displeasing, chromatic aberration, dithering, halftone, screentone, multiple views, logo, too many watermarks, negative space, blank page
```

- **冲突项直接删（只删不换）**：与当前画面意图冲突的条目删除即可，不替换成别的（要胶片颗粒感就删 `film grain`，做条漫就删 `multiple views`）。
- **多人图不从单人模板照抄**：模板里若有 `extra characters` 一类排斥多余人物的条目必须删除——它会跟人数 tag 打架。
- 默认不给负面词；用户要时按 negative.md 按需定制（8–15 条、每条能说出对这张图为什么重要、不抄固定套餐）。

### 容量

- Full 容量 1471 token / Curated 703。
- 画中文字：Full 750 字符 / Curated 374。

### V4.5 与 V3 的差异

- **V4.5**：写法与 V5 基本一致，两处旧机制不写——`{}` 权重用数值语法替代；5×5 网格 Position 是旧机制，V5 用自由画布（Custom position）。数值权重在 V4.5 感知更钝，需 3.0–4.0 才有 V5 1.3–1.8 的同等强度。
- **V3 及以下（识读）**：`|` 是 prompt mixing，不能用于多人；`{{}}`/`[[]]` 为旧权重语法。读旧串理解即可，产出一律按现行语法写。

## SD 系（SD 1.5 / SDXL / Pony / NoobAI / Illustrious）

A1111 系界面的括号权重体系，Danbooru 惯用拼写，tag 为主体。Pony、NoobAI、Illustrious 是 SDXL 系的社区模型，写法同宗。

### 输入体系

- Danbooru tag 为主体，按画面需要混用英文自然语言、自由英文短语——动作、空间关系、构图、概念融合交给短语和短句表达。
- 不设句数、tag 数量或总长度上限，画面完备优先。
- 遵守用户的明确要求（纯 TAG、只清理等），沿用用户指定的平台。

### 权重语法（A1111）

- `(tag)` ≈×1.1；`((tag))` ≈×1.21；`(tag:1.3)` 精确权重；`[tag]` ≈×0.9；`[tag:0.3]` 弱化（有地板效应，不会完全消失）。
- **本体系没有负权重语法**：括号与方括号只有正向加权与弱化两档，不存在「负权重」。要排除元素走**独立的负面提示词字段**（见 negative.md），或按 negative.md 第一原则写进正文的具象化排除。
- 需要字面括号时用 `\/` 转义。
- 默认不加权；加权时核心概念高于支撑概念。跨模型换算规则与SD 权重不能表达的内容如何处理 → convert.md §权重语法换算。

### 进阶语法（需要时才用）

| 语法 | 效果 |
|---|---|
| `(a AND b AND c)` | 多概念同时渲染在画面中 |
| `[cat\|dog\|bird]` | 交替提示：每步采样轮流切换，产出融合体（不是拼接，是混血）；如 `[jellyfish\|lantern\|raindrop]` = 三者特征的新生物 |
| `[from:to:0.3]` | 步数切换：前 30% 步用第一概念构图，之后切换细化；前期步数管大结构、后期管细节，切换点 0.2–0.5。创作应用：`[underwater:dreamscape:0.3]` = 用水下物理感打底再叠梦境质感 |
| `(a\|b\|c)` | 管道切换：括号内局部混合 |
| `(red OR blue OR green)` | 随机选一，批量出变体 |

- 部分语法取决于界面或扩展支持，使用前核对目标环境。

### 分隔符强度梯度

`,`（逗号，软连接，元素保持关联）< `.`（句号，硬切，阻止前面的 token 污染后面）< `BREAK`（最硬切割，区域级隔离）。

### 多人机制

- `prompt for region 1 BREAK prompt for region 2` 配合 Regional Prompter 插件做行/列区域分割，每区域独立控制 prompt；Divide Ratio 控制区域大小（`1,1,1` 等分 / `2,1,1` 首区加倍）；`ADDBASE` 为全局基础 prompt。
- BREAK 是比 AND 更强的概念隔离。
- **不要把 NovelAI 的角色竖线 `|` 当 SD 多人语法**。

### 拼写与社区惯例

- Danbooru 惯用拼写：`1girl`、`twintails`、`thighhighs`、`looking at viewer` 等；统一空格形态（`long hair`）。
- **NoobAI / Illustrious**：社区惯例用质量前缀（masterpiece / best quality 等）与年代词（newest 等）起手——按统一裁决**不写**；用户明确要求按社区完整格式时才补。
- **Pony**：惯例用 `score_9`–`score_1` 评分标签（下划线形态保留）——默认不写；用户点名 Pony 且明确要求时才按需使用。

### 负面词

- SD 系有独立 negative prompt 字段。负面词默认不给；用户要时按 negative.md 定制。

## Anima

同时训练了 Danbooru 标签与自然语言字幕；纯标签（默认）、纯自然语言、混合三种写法都合法。拼写全小写、空格分隔（`score_*` 例外保留下划线）。Base / Aesthetic / Turbo 三个版本在写法上只差质量标签一处——本skill输出统一形态，用户声明版本时才切换。

### 正向组装顺序

```
[数据集标签（可选，置最前）] → 人数 → 角色 → 系列 → @artist → 一般标签
```

- **数据集标签** `ye-pop` / `deviantart`：调用训练集中非动漫的艺术画数据（水彩、厚涂、西方插画），要艺术画方向才加，置于提示词最前（官方为首行、后接换行）；不要写实/西式风时不加。
- 人数标签画面有人物时必写，是构图第一锚点；纯风景/静物不写（用户要负面词时提示在负向补 `1girl`/`1boy` 防人物乱入）。
- 角色 → 系列成对出现；多角色时每个角色名紧随其外观描述组。
- 一般标签内部无硬性顺序，按「主体特征 → 服装 → 动作姿势 → 场景 → 构图镜头」聚类。

### @artist 强制

- artist 标签必须加 `@` 前缀（`@big chungus` 形态）；不加会被当普通词处理，风格调用失效。
- 画师标签用户点名才写。

### \(reverse:1999\) 转义

- 角色消歧括号必须转义：`vertin_(reverse:1999)` 写成 `vertin \(reverse:1999\)`。不转义时 `(reverse:1999)` 的括号+冒号被权重语法解析成「标签 `reverse`、权重 `1999`」——极端异常值让模型直接输出未去噪的原始噪声（满屏彩色噪点、无正常画面）。
- 系列标签 `reverse:1999` 不带括号、原样写——它在括号外，冒号不触发权重语法。
- 不想带消歧括号时，与用户确认后可去掉。

### 权重

- `(tag:数值)` 有效，但响应阈值高于 SDXL：常规 1.1–1.3 几乎无效，**1.5 起步**，强强调用 `(chibi:2)` 级别。
- 默认不加权；用户明确要求强调才加，且优先换更精确的标签而不是堆权重。

### 自然语言与混合

- **纯自然语言**：至少写满两句，单句效果差；角色/系列名用标准大写（`Hatsune Miku`）。
- **混合**：artist 标签放在 NL 部分之前，任意交替均可；写 NL 时**先点名角色再描述外观**，多角色场景尤其如此。
- 仅在用户明确要求自然语言风格时才输出 NL 形态，默认标签形态。

### 已知限制

- **不擅长写实摄影**：真人照片质感不是训练目标，不接写实人像需求——可建议 `deviantart` / `ye-pop` 艺术画方向替代。
- **文字渲染弱**：单词级可行，长句会崩；画面需要文字时控制在单词量级。
- **短 prompt 风险**：过短的正向（如只有 `1girl`）会让模型自行脑补到奇怪方向——把画面要素问全。
- **标签 dropout**：训练时随机丢弃过标签，不追求穷举——写立住画面的关键标签即可，堆满反而稀释权重。
- **不写内容分级前缀**：本 skill 一律不输出 `safe` / `sensitive` / `nsfw` / `explicit` 及 `rating:*` 前缀——模型按自身训练分布推断画面倾向，无需显式声明（Anima 官方格式不因此失效）。

### 负面基础集（用户要负面词时的参考池）

```
worst quality, low quality, artist name, blurry, jpeg artifacts, chromatic aberration
```

- `artist name` 压画面里出现的签名/水印文字。
- `score_1, score_2, score_3` 仅 Turbo / Base 版本负向使用；任何版本的正向都不堆 score 标签。
- 微调克制：每处追加都要能说明理由（拒绝写实感补 `photorealistic, realistic`；画面出现乱码文字/水印补 `logo`），不做防御性堆砌。

## NewBie（XML 结构流）

结构化 XML + caption 自然语言双层输入的模型格式。

- **动笔前先做情境因果锁**（五步）：发生了什么 → 触发什么情感 → 引发什么反应 → 环境如何参与 → 最抓眼球的瞬间是哪一刻。
- **XML 三层结构**：`<img>` 根节点下——多个 `<character_N>`（子标签 `<n>` `<gender>` `<appearance>` `<clothing>` `<expression>` `<action>` `<position>`）+ `<general_tags>`（`<count>` `<style>` `<background>` `<atmosphere>` `<quality>` `<resolution>` `<artist>` `<objects>` `<other>`）+ `<caption>`。
- **caption 是空间叙事层**：镜头取景、光线、色彩、互动归属、接触关系、因果后果——只写标签装不下的关系信息，**不重复标签内容、不写 style/quality 词**。
- **拼写（统一裁决的登记例外）**：标签内空格转下划线——与统一裁决的空格形态相反，NewBie 结构槽是唯一这类例外（见 §统一裁决）；字面括号反斜杠转义，权重括号不转义。默认画风词 `anime_style, realistic_shading`（用户指定风格则替换）。
- **八维补全检查**（交付前）：互动/情感/视线/联动/动势/空间/质感/因果至少触发三维，缺维由 caption 补全。
- quality 槽的 `very_aesthetic, masterpiece` 与 `max_high_resolution` 是该格式官方默认——按统一裁决不写，槽位留空或删槽；用户明确要按官方完整格式时才补。

## Qwen-Image（观察者式 JSON 契约）

输出为 JSON：t2i 两字段 `{"rewritten_prompt", "wh_ratio"}`；i2i 增 `ratio_follow`（值为 `<image1>`）与 `wh_ratio` **互斥**（跟随原图比例时不给 wh_ratio）。

- **t2i**：约 20 句、400-500 词；开头固定句式 `The image is a ⟨orientation⟩ ⟨style⟩ ⟨medium⟩ of ...`——**medium 名词不可省**；空间采用**分区游走**（背景 → 顶带 → 左/中/右 → 底带），约 1/3 句子以方位短语开头；图内文字加直引号并保留原语言；光照独立成句；结尾唯一一句 `The overall composition ...`；**比例只进 `wh_ratio`**（默认 3:2 / 2:3），描述内禁止出现比例/分辨率/质量词。（`wh_ratio` 是**契约字段**、不是参数建议，属 SKILL.md §一「提示词字符串内部语法」的豁免，与 MJ 的 `--ar` 同类，正常输出。）
- **i2i 双语决策**：(A) 描述语言随用户指令；(B) 渲染文字的语言优先级 = 用户指定 > 图内已有文字的主导语言 > 指令语言，且引号内单语。
- **核心原则「属性解耦」**：编辑强度与保留范围分开声明——"Preservation locks content, never edit strength"（保留清单锁内容，不锁编辑力度）；两类失败对称防范：Leakage（该改的被保留锁死）/ Under-editing（该留的被改掉）。
- 多图必须用 `<image1>` 标签引用并声明哪张是画布图；扩图按比例推断表、三视图/宫格自适应比例。

- 自然语言完整句子组织，无负面体系、无权重语法、无质量 tag——按 nl-flow.md 八段骨架写。
- 出图端参数（CFG 4.0 等）不进正文、不主动建议。

## WAI-Illustrious（社区 NSFW 主力）

- 格式与 SD 系完全同构（A1111 括号权重、Danbooru 惯用拼写、负面字段存在）；**负面词仍按统一裁决默认不给**（见 §统一裁决、negative.md），只有用户开口要时才给。
- 社区惯例质量尾（`masterpiece, best quality, absurdres`）按统一裁决**不写**；Clip Skip 2 是其训练默认——属用户端设置，不是提示词内容。
- 成人画面组装按 nsfw/tags-techniques.md §组装层级；负面词按 negative.md §B 模式负面词（成年防御块最前）。

## Midjourney

- **形态**：精炼、意象密集的英文短句/词组，逗号分隔；不吃长篇空间描述与长句。
- **强项**：美学与风格化表现；把它当「氛围与意象压缩器」，不当「场景说明书」。
- **尾参属提示词内语法，正常写**：`--ar`（比例）、`--niji 6`（二次元）、`--stylize`（风格化强度）、`--sref` / `--cref`（风格/角色参考）等。Midjourney 的 `--ar` 是例外——那是它自己的语法；其他模型要表达画幅，用一句构图语言（`a wide 16:9 horizontal composition`）或留给出图端设置，**不输出任何参数建议**。
- **负面**：`--no` 属正文语法，可写但效果有限；更稳的做法是把排除结果写成正向的场景描述。负面词默认不给。
- **多人**：无专用机制，人数与位置关系靠句内点名，保持精炼。
- 英文优先。

## Flux / Nano Banana（Gemini）/ GPT-Image

自然语言理解强的一档：吃完整句子与空间关系，按自然语言流写法组织。

### 共同规则

- **完整句子与空间关系**：位置写进句子——`on the left`、`behind her`、`in the foreground`；按六层信息序组织（主体与动作 → 外貌 → 服装/材质 → 场景氛围 → 镜头/光线 → 风格），可以写得更具体。这六层是 §组装顺序总则 六段通则的**压缩表述**，不是另一套排序。
- **不加尾参**：任何 `--` 参数都不是它们的语法；要表达画幅就用一句构图语言，其余留给出图端设置，不输出参数建议。
- **无权重语法**：强调靠措辞精度与前置位置，不靠权重符号。
- 负面词默认不给。

### Flux

- 也接受逗号分隔的词组流；有独立负面提示词字段，用户要负面时才用。

### Nano Banana（Gemini）

- 自然语言长句，中文可用；强指令跟随、强文字渲染、强图像编辑。
- 描述过碎会稀释——保持句子完整、信息分层，不堆碎片词。
- 编辑任务显式写「只改 X，其余不变」。

### GPT-Image

- 指令式自然语言；指令跟随极强，文字与排版准，能精确控制物体数量。
- 数量与位置要精确写（几个、在哪、朝向）；别用 MJ 式参数语法。
- **画幅先行**：画布、比例、版式声明放主体描述之前。
- **JSON/config 型 prompt 是核心模式**：信息图/图表/UI 类用固定区域 schema 逐区声明（每个区域写清内容+位置+样式），提示词读起来像产品规格而不是散文。
- **场景密度胜过形容词**：可画的具体细节清单优先于"高质量/精美"类抽象词；风格锚点要具体有界（说清媒介与边界，不堆风格名）。
- **材质、光照、配色是三个独立控制项**：分开声明，不混在一句里。
- **否定句只用于强先验**：对模型默认倾向极强的项才写否定（"无水印"），普通排除项改写为正向场景描述（与 negative.md 具象化原则同源）。
- **编辑类指令必须保留不变量**：编辑任务显式写"只改 X，其余完全一致"清单（与 Nano Banana 编辑规则同源）。
- **中英混排密集版式**（海报/包装）：逐字给出双语文字内容、字体归属与区域位置，额外写清对齐与留白约束。

## Seedream / 即梦 / 可灵

- **中文自然语言**：接受中文，按六层信息序直接写中文，不硬译成英文腔；避免过长的英文技术词（收益低）。六层是 §组装顺序总则 六段通则的压缩表述。
- **Seedream / 即梦**：中文语境强，海报与文字排版强，国风题材强。
- **可灵**：动作描述直白、具体，不抽象。
- 无权重语法、无尾参；负面词默认不给。

## Krea

两种模式不叠加，先判任务再写：普通插画（角色图/场景图）走中文自然语言；图文海报（用户明确指定 Krea 且任务是海报、图文海报、视觉传达海报或同类平面设计）走专用英文海报模式。

### 普通插画模式

- **一段完整连贯的中文自然语言**，依次组织：主体外貌 → 动作姿势 → 人物或物体关系 → 构图 → 环境 → 光线 → 材质 → 风格。
- **禁用**：Danbooru TAG、括号权重、BREAK、额外的英文动作句。

### 图文海报模式（纯英文海报段落）

五维详写：每项视觉维度都要详尽、繁复、有视觉张力与想象力，同时保证整体画面合理、统一、可执行；各段用自然流畅的逻辑过渡，涉及画面文字时注意合理分段；画面中的文字内容必须与主题、主体、背景存在直接或间接联系。各维度中的示例词汇只用于解释，不是必选项或固定词库——按实际海报自由创造。

1. **风格、艺术表现与渲染色彩**：以一个主导风格为核心（确有设计理由才多风格碰撞融合或形成局部差异）；建立严格的色彩控制系统——主色、辅助色、极少量点缀色，防止色彩失控；刻画材料与表面质感（网点纸纹、全息镭射反光、故障噪点、水彩晕染等）；需要写实或高级光影时用准确的渲染术语（`global illumination`、`caustic rays`、`shallow depth of field`）。
2. **主体与核心刻画**：主体选择服务海报整体——可以没有明确主体，也可以是角色、纯文字、纯场景、核心商品、巨型机械或抽象雕塑，形式可独立或组合。角色拆到性别/年龄/种族或身份/体型/发型走向/发色/瞳色/五官气质，服装的全部层级、材质、配饰，身体姿态/肢体关系/面部微表情/视线落点——只写服务当前海报的特征，不机械穷举；非人物主体同样拆解外观、结构与材质；纯文字主体可把字母建筑化、实体化、特效化（字母拆成金属柱体、电路隧道等空间结构）；IP 角色写官方英文名与作品英文名（`Makima from Chainsaw Man` 形态），在辨识特征准确的基础上做符合海报美学的演绎。
3. **背景、场景与环境特效**：具体描述画面里真实存在的颜色区域、线条、建筑、平面模块和空间结构，不用宽泛场景名代替设计；辅助元素（悬浮几何碎片、发光蝴蝶、碎玻璃、花瓣等）写明空间分布；魔法/能量/物理视觉特效写颜色、方向、起点、运动轨迹以及与主体的遮挡关系。
4. **字体排版系统与特效**：画面文字用双引号写确切内容；以较短的英文、数字、偶尔日文为主，避免连续大段文章；写字体样貌（无衬线粗体、优雅哥特体、未来线框体）并赋予海报特效（垂直拉伸、镂空描边、水波扭曲、错位故障重影、条形码模块、UI 模块）；建立文字视觉层级——主标题、副标题、引言、作为排版材质的微型元数据块（坐标轴、版本号、版权说明、UI 指示符）；每组文字写明位置、尺寸、对齐方式与空间锚点，以及与主体之间的遮挡、穿插、环绕关系。
5. **镜头、构图与空间层次**：镜头距离、视角、角度和景深；构图法则（非对称平衡、网格系统、动态对角线切割），允许对画框做物理分割（如两侧用填满文字排版的纯白垂直栏、中间承载主插画）；明确负空间及前景/中景/背景层次，位置具体到象限与区域（左上象限、画幅右侧三分之二、绝对中心点）；描述正负空间的切割逻辑（如一条笔直的红色对角线划分纯白与黑色区域）；建立图层遮挡逻辑——文字位于哪些背景图案之上、又被人物手臂/服装/商品等前景实体遮挡，确保所有空间关系能被画面直接呈现。

## DALL-E / Ideogram（简要）

- **DALL-E**：自然语言完整句，排版指令明确写出（什么文字、什么位置、什么层级）；数量与位置写实。
- **Ideogram**：文字 / Logo / 海报渲染最强；要出现在画面上的文字用双引号明确给出，其余内容用自然语言描述。
- 共同：无尾参、无权重语法；负面词默认不给。

## 跨模型转换注意

转换是换表达形态，不是换画面内容：先按语义单元拆解源提示词（主体/动作/外貌/服装/场景/构图/光线/风格/权重层级），再按目标模型重组。完整工作流与权重换算权威见 convert.md，这里记形态与结构映射及切换检查。

### 形态映射

| 目标 | 做什么 |
|---|---|
| → 标签流（NAI / SD / Anima） | 句子拆成 tag，保留必要的关系句；权重按目标体系重标 |
| → 自然语言流（Midjourney / Flux / Nano Banana / GPT-Image 等） | tag 串改写成完整句子；权重语法整体删除，强调改为措辞精度+前置位置 |
| → Krea 普通插画 | 全部改写成一段连贯中文，删除一切 tag / 权重 / BREAK 痕迹 |
| → Krea 图文海报 | 按五维重组为纯英文段落 |

### 权重换算

权重换算以 [convert.md](convert.md) §权重语法换算 为权威（完整换算表、数值重定标、数字结尾 tag 处理）。核心一条：**NAI 与 SD 括号体系相反，必须转换，不照搬**——感知强度不跨模型直译，数值按目标体系常用区重定标。

### 结构映射

- **多人**：NAI `Character N:` 字段 ↔ SD `BREAK` 分区（+Regional Prompter）↔ 自然语言模型的句子分工。NAI 的施受前缀 `source#` / `target#` / `mutual#` 与 Custom position 深度没有对应物——转成句子描述动作方向与前后层次。
- **画中文字**：引号法在 NAI / Ideogram / Krea 海报通用；转写时保留「双引号 + 载体 + 位置」三要素。
- **尾参**：`--ar` 等 Midjourney 尾参只属于 Midjourney，转其他模型一律删除；比例意图改写为一句构图语言，不输出参数建议。
- **质量前缀与年代词**：任何模型都不写（统一裁决）——迁移时直接删，不为「保留官方格式」而补；用户明确要求才补。
- **UC / 负面**：各模型负面体系不同（NAI UC 串、Anima 基础集、SD 独立字段、Midjourney/GPT-Image/Gemini 写进正文），默认不给；用户要时按 negative.md 按需定制，**不跨模型照抄**。

典型反面教材：把 Midjourney 的 `--ar 16:9 --style raw` 原样贴给 Gemini；把 Gemini 的六百字长句原样贴给 SD。迁移时先拆解、再重排、补上目标模型约束、删净源模型专属语法。

### 切换模型检查清单

切换模型时逐项确认：

- [ ] 形态改了吗（标签 ↔ 句子）
- [ ] 权重语法换算了吗（`::` ↔ 括号 ↔ 删除）
- [ ] 负面词位置改了吗（UC 字段 ↔ 独立字段 ↔ 写进正文 ↔ 不给）
- [ ] 语言改了吗（英文 ↔ 中文）
- [ ] 专有语法清干净了吗（Midjourney 尾参、NAI 前缀语法、`Text:` 块、`|` 竖线）
- [ ] 质量前缀与年代词没有被带过去吧（一律不写）
