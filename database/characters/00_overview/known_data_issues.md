# 已知数据问题

本文档集中记录清洗与构建阶段识别的数据异常及处理方式。所有处理均**保留来源、不臆造**。

## 1. Danbooru 杂散值（D2944）
`danbooru_tags_min1000.xlsx` 第 D 列第 2944 行存在一个杂散数值，属非正式字段。
- **处理**：正式热度只取 C 列；D2944 的值**不进入任何标签的热度**，仅在此登记。
- 该异常已入库 `data_warnings` 表，可追溯。

## 2. 颜文字标签 `=_=`（第 1286 行）
`=_=` 为合法的颜文字标签，**非公式、非错误**。
- **处理**：`tag_raw / tag_canonical / tag_display` 三者**均原样为 `=_=`**，不做下划线转空格。
- 同类纯符号/颜文字标签（如 `^_^`、`>_<`、`0_0`）一律保留原样。

## 3. 角色外貌提示词缺失
共 276 个角色缺少核心外貌提示词。
- **处理**：文档标注「（来源中未提供）」并加 ⚠️，**不代填、不猜测**。

## 中文名字段错位（2026-10-06 实测登记）

**现象**：角色库的中文名字段存在**大面积错位**——同一个中文名被填给多个不同角色。

- 角色条目总数 8,906（by_work 7,767 + pooled 1,139）
- 被 2 个以上英文名共用的中文名：**92 个**，涉及 **215 个条目**（2026-10-09 实测复核；原记 85/198 已过期）
- 最集中来源：`pokemon`（107/215，约 50%）

**典型案例**：

| 中文名 | 被填给的英文名 | 正确对应 |
|---|---|---|
| 小火龙 | oshawott / squirtle / cyndaquil /charmander / togepi / turtwig / growlithe | 宝可梦历代译名混乱 + 明显错位（oshawott=木木考察官） |
| 皮卡丘 | pikachu / **clefairy** | clefairy 应为「皮皮」 |
| 月石 | umbreon / **lunatone** | 应为「月亮伊布」/「月石」 |
| 你好杰克 | **8 个不同作品的角色**（eve_(elsword) / hoshino_fumina / haruka_(blue_archive) / inumuta_houka / kotonoha_aoi / maki_oze / motoori_shiro / revenant_(apex_legends)） | 各角色均应为自己的正式中文名 |

**已处理**：「你好<TAB>杰克」中的内嵌 TAB 已**直接删除**（非替换为空格，最终值为「你好杰克」，消除表格解析破坏），**角色条目与索引行全部保留，未删除任何角色**。

**使用建议**：
- **检索以英文名为准**——英文名是唯一可靠字段，Danbooru tag 也是英文形态。
- 中文名仅作辅助参考；命中中文名时**必须回看英文名确认是否同一角色**。
- 同一中文名对应多个角色时，向用户列候选并按作品区分，不擅自选定。

**未处理的原因**：修正中文名需要逐条查证官方译名（8,906 条中涉及 92 组），超出本次重整范围；且部分错位无法从现有数据推断正确值（源数据本身已损坏）。已在 index 中保留全部条目供回溯。
